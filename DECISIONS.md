# Decision log

Short records of decisions made while building. Owner decisions live in `docs/MASTER_INBOX.md`, and the stack decision lives in `ADR/000-stack-and-hosting.md`. D-numbers here are routine engineering calls unless marked otherwise.

| ID | Date | Decision | Why | Reversal |

| D-001 | 2026-11-06 | Keep proofs in `spikes/p0.2/`, apart from app code | They are throwaway measurements, not a starting point | Delete the folder after P1 |
| D-002 | 2026-11-06 | Measure CPU two ways: V8 profiler and OS process time | The profiler adds about 2 ms and is noisy. Process time is the steadier upper bound | Replace both with Cloudflare's reported CPU time at P1.5 |
| D-003 | 2026-11-06 | Runtime role has no DELETE anywhere; a separate cleanup role purges | Reset and expiry never need destructive rights in the request path | None planned |

| D-006 | 2026-11-06 | ~~Purge function does not use `FOR UPDATE`~~ Superseded by D-012 | The first proof run failed: row locks need UPDATE privilege, which the cleanup role lacked | D-012 |
| D-007 | 2026-11-06 | Google service account, not an owner OAuth token | It can only reach the one sheet shared with it. RS256 signing is cheap enough to do in the Worker | Owner refresh token if signing proves too slow in production |
| D-008 | 2026-11-06 | Biome for format and lint | One tool, one config, no plugin chain | Move to ESLint if a rule is missing |
| D-009 | 2026-11-06 | npm with a committed lockfile | Already installed, and pnpm would add a tool for no benefit here | None |
| D-010 | 2026-11-06 | ERP and CRM simulators live in the same Worker | PRD 2.7: fewest runtime services | Split if simulated faults ever affect app latency |
| D-012 | 2026-11-06 | Purge and workspace changes run in `SECURITY DEFINER` functions; cleanup role has no table rights; runtime role can't write `workspaces` | Independent review showed that table-level DELETE let cleanup reach owner rows, and UPDATE let a bug turn an owner workspace into a purgeable demo | None |
| D-013 | 2026-11-06 | One approval row per entry to Ready | Keeps the idempotency key simple and gives each decision its own record | None |
| D-011 | 2026-11-06 | Postgres 17 locally | Current Neon default range; recheck the major version when the project exists | Change the compose image |
| D-014 | 2026-11-06 | Keep raw parameterized SQL through `pg` for P1 and leave Drizzle out for now | P1 has a handful of queries and most logic sits in SQL functions, so a query layer would add a dependency with nothing to do. | D-015 | 2026-11-06 | Use `jose` for JWT verification rather than hand-written WebCrypto | Algorithm and claim handling is the wrong place for local cleverness. It is a small, free library with no dependencies | None |

| D-018 | 2026-11-06 | Runtime role has no table rights on sessions, quota, users or memberships | Narrower than PRD 7.4 requires. A query bug can't read token hashes | None |
| D-019 | 2026-11-06 | One `launch_demo_session` call does quota, workspace, seed, session and audit | One round trip and one transaction, which matters on the 10 ms CPU budget | Split if a later phase needs a step in the Worker |
| D-020 | 2026-11-06 | Add a title-only `PATCH /cases/{id}` and read-only list and detail at P1 | The isolation matrix needs a real write path to test. Status moves stay in P2 | Replaced by the full route at P2.2 |
| D-021 | 2026-11-06 | Small History API router instead of a routing library | Eleven routes and one focus rule. No dependency needed | Adopt a router if nested data loading appears |
| D-022 | 2026-11-06 | Stay on TypeScript 5.9.3, advice only | Per the P1 brief's upgrade check: 7.x is available, but nothing here needs it, and a compiler major belongs in its own change | Review at P7 |
| D-023 | 2026-11-06 | Reset keeps the demo role and rotates the token, on the same session row | The visitor keeps their place in the story, and the old cookie dies at once | None |
| D-024 | 2026-11-06 | The owner workspace is seeded with synthetic rows, one owner workspace only | Lets "two guests plus owner" be tested before any real owner exists | None |
| D-025 | 2026-11-06 | Demo limits live in a migrator-owned table, not Worker variables | Independent review showed a Worker secret or a leaked app credential could stretch the 24-hour rule and the cap | None |
| D-026 | 2026-11-06 | Reset spends the launch budget, and IPv6 counts by /64 | Review showed one client could make 30 workspaces an hour against a purge of 10, filling the cap for everyone | Separate reset budget if real use shows families sharing an address get blocked |
| D-027 | 2026-11-06 | Own small JWKS cache rather than `createRemoteJWKSet` | jose's remote set shares a pending fetch between callers, which workerd's request-scoped I/O doesn't allow across requests, and a per-request set defeats its cache | Revisit if jose or workerd changes |
| D-028 | 2026-11-06 | Runtime grants stay narrower than PRD 7.4 until a phase writes a table | P2 has RLS and write policies on every new table, but `opsbridge_app` gets only SELECT on tables no P2 route writes. | D-029 | 2026-11-06 | Fictional consultants live in `app.assignees`, not `memberships` | Memberships are real sign-ins that the runtime role must not read (D-018). A demo has no real people, and assignment needs a table the runtime can join | Merge only if real multi-user workspaces ever exist |
| D-030 | 2026-11-06 | Keep raw parameterized SQL at P2.1 and leave Drizzle out, closing D-014 | Most logic is in SQL functions or a handful of repository queries with row locks and keyset branches, which a query builder would not simplify. No new dependency | Revisit if P3 adds many plain CRUD queries |
| D-031 | 2026-11-06 | Every workflow command takes the case row lock with `FOR UPDATE` before checking anything | One lock order for transitions, checklist, handoff and approvals. A canary shows a checklist change slips past a transition without it | Drop only if Hyperdrive proof shows it can't hold |
| D-032 | 2026-11-06 | Purge waits 60 seconds past expiry and locks sessions before the workspace | A deadlock between reset and purge was reproduced. The wait also keeps purge clear of any request that passed its session check just before expiry | None |
| D-033 | 2026-11-06 | One write cap per demo workspace, enforced by a trigger on `audit_events` | Every write audits, so one check bounds cases, handoffs and everything else, and only a migration can change it. Default 500 | Per-table limits if one table proves to need its own |
| D-034 | 2026-11-06 | The outbox stores the whole event envelope as `payload`, beside `payload_ref` | The envelope is built in the business transaction and holds only short references, so P4 sends what was committed and rebuilds nothing | Move to references only if payloads ever carry content |
| D-035 | 2026-11-06 | `POST /cases` goes straight to Intake unless `draft: true` | The journey and E2E-05 expect a created case to emit its event at once. Draft stays available and emits when it moves | None |
| D-036 | 2026-11-06 | Idempotency claim row, then response, in the command's transaction | A duplicate waits on the unique key and replays the committed result, and a failed command leaves no key, so a retry runs for real | None |
| D-037 | 2026-11-06 | The ERP Simulator speaks HTTP shapes, in process | Adapters take a `Request`-to-`Response` transport, so their error handling and paging run as they would over a network, without a second server or an open port. It also keeps the simulator off any public route | Mount it on a route only if a separate tool needs it |
| D-038 | 2026-11-06 | The ERP sync reads through SuiteQL, not record collections | A collection returns ID stubs, so fields would cost one call per row against a concurrency limit | Revisit against a real sandbox |
| D-039 | 2026-11-06 | `source_records` holds the allowlisted fields of every CRM and ERP record, apart from canonical tables | An unmapped record needs somewhere to be evidence without becoming a customer. PRD 7.1 asks for provider data to stay minimal and segregated | None |
| D-040 | 2026-11-06 | Ingestion never writes a canonical customer. Only an exact cross-reference to one bill-to, or a person, can add a link | A sync that creates customers is how false duplicates start, and it would make replay depend on order | None |
| D-041 | 2026-11-06 | Pack findings are generated by the real engine at seed time, and `dedupe_key` leaves timestamps out | A first sync recognizes them and adds no duplicate, and the seed can't drift from the rules. `reconcile.ts` and `mappers.ts` stay free of value imports so plain Node can run them | None |
| D-042 | 2026-11-06 | A resolved or dismissed finding stays closed, and new evidence is a new row that supersedes the old | The state machine forbids reopening, and an audit reader must be able to see what was decided on which facts. A superseded finding can't be approved | None |
| D-043 | 2026-11-06 | Guests get a separate simulated sync route, beside the owner route in PRD 8.2 | The demo has to show ingestion. The guest route can only build a simulator, so a bug in it can't reach a live source. Not a scope change: PRD 5.3 needs the simulated CRM sync | None |
| D-044 | 2026-11-06 | Tokens are AES-256-GCM in `connection_secrets`, with the key in a Worker secret | PRD 8.3 allows an encrypted store with an independent key. No new paid service, and the runtime role can't delete, so disconnect scrubs the row | Move to a secrets service if one is ever approved |
| D-045 | 2026-11-06 | Salesforce read-only is enforced in code and by the connected user, not by scope | Salesforce has no read-only OAuth scope | Revisit if one appears |
| D-046 | 2026-11-06 | Hosted runs do one page per request, and the client continues | A whole ERP sync measured about 20 ms of CPU under Node, against a 10 ms limit on Workers Free. The measurement isn't workerd's, so the first deploy must measure it again | Raise `SYNC_PAGES_PER_CALL` if the real number allows |
| D-047 | 2026-11-06 | A scenario applies to one run, and an operator resume clears its fault | Simulated recovery has to look like a source that came back, and the list of scenarios stays closed so no fault detail comes from the request | None |
