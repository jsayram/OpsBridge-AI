## Goal and business reason

The server-side path a real model would use, built now so that only a key and a budget are missing. Proves the P5.3 row locally and E2E-14.

**Plain language.** Only the owner can ask for a live review, and only when a flag, a key and limits are all set. The destination is fixed in code. Each call has a timeout, a token cap, a daily request cap and a concurrency cap, all counted in the database, so nothing can loop and spend. If anything is missing or fails, the owner gets the labeled fixture result instead and a clear code. Until Jose provides an account and a budget this runs only against a labeled double, and P5.3 stays Pending Owner Credentials.
