## Goal and business reason

Show the hard part of connecting business systems: two sources disagree, and the app shows the evidence and lets a person decide. Proves P3-A to P3-H, JOB-03, JOB-11, JOB-19, JOB-20.

**Plain language.** P2 proved the app keeps its own records straight. P3 brings in simulated CRM, ERP and inventory data, runs the same sync twice without duplicates, and turns each disagreement into a finding with the source values attached. Nothing merges on a similar name.

## Must carry forward from P2

- Migrations `0001` to `0003` are frozen. New work starts at `0004`. A changed checksum stops the runner.
- `opsbridge_app` holds only SELECT on `external_record_links`, `customer_source_relationships`, `reconciliation_findings`, `inventory_items`, `inventory_snapshots` and `workflow_rules` (D-028). Widen each in the migration of the package that writes it, and update the exact-grant test.
- Those tables already have RLS, write policies, composite keys, pack copies and purge entries. Any new table needs all of them, plus a line in `purge_demo_workspace` and `seed_demo_workspace`. `schema.test.ts` sweeps every table with a `workspace_id` after a purge, so a missed one fails.
- `external_record_links.canonical_id` and `reconciliation_findings.entity_id` have no foreign key because they point at more than one table. Application code must scope them to the workspace, and a test must prove it.
- Every workflow command takes the row lock first (D-031). Do the same for findings, with `version` checks, and keep one lock order: case, then finding, if a command ever needs both.
- Every write audits through `writeAudit`, which also counts against the demo write cap (D-033).
- Commands that create or resolve use `Idempotency-Key` through `idempotent()`. Stored replies are JSON, so key order may differ on replay.
- Events go through `emitEvent` inside the business transaction. `reconciliation.resolved` is keyed `finding:{id}:resolved`.
- Template seed rows use the fixed clock so two clean seeds match. A default of `now()` in a seeded column fails the comparison test, which is how P2 caught `next_attempt_at`.
- Contacts and invoices have no table yet. P3 adds them and extends the generator to the PRD 16 counts, and they stay out of the pack unless the journey needs them. Keep the pack at 40 rows or fewer.
- Template outbox rows are seeded history. Three sit in `pending`, so P4's claim function must filter out template rows, as `STATE-MACHINES.md` says.
- Local runs need Node 22 on the path. The default shell is Node 26, and CI uses 22.
