# P4 — Durable automation and Zapier: phase brief

Status: planned, not started. Prepared at: 2026-11-06 America/New_York by the P3 phase session. PRD: v1.4, hash in `docs/DOCUMENT-SYNC.md`. Coordinator: master thread `local_2ce00b84-dd6c-4a69-9efd-3a293bde5688`.

## Goal and business reason

Make approvals and resolved findings produce reliable, controlled automation effects. Proves P4-A to P4-E, JOB-12, JOB-18, JOB-24.

**Plain language.** P2 and P3 write events into a durable outbox and stop there. P4 delivers them, and tells the truth about how far each one got: queued, accepted by a provider, confirmed by evidence, failed, or simulated.

## Must carry forward from P3

- Migrations `0001` to `0006` are frozen. New work starts at `0007`. A changed checksum stops the runner.
- `opsbridge_app` has SELECT on `workflow_rules` and only SELECT and INSERT on `outbox` (D-028). The dispatcher changes outbox rows through the P4 functions, not through grants. Widen rules in the migration of the package that writes them, and update the exact-grant test.
- The outbox already receives `reconciliation.resolved`, keyed `finding:{id}:resolved`, and `integration.degraded`, keyed `integration:{connection}:degraded:{run}:{resumes}`, once per transition into Degraded. Both have envelope types in `backend/src/domain/events.ts`, and data holds short references only.
- Template outbox rows are seeded history, and three sit in `pending`, so `claim_due_outbox` must filter out template rows, as `STATE-MACHINES.md` says. Test it.
- Long work on Workers Free: use `SYNC_PAGES_PER_CALL` as the pattern. One bounded step per request or tick, with durable position, and no transaction across a network call. The sync measured about 20 ms of CPU under Node against a 10 ms limit, so the first deploy has to measure real numbers.
- The sync's lease, cursor compare-and-set and connection-then-run lock order in `backend/src/repo/sync.ts` are a working model for the dispatcher's lease.
- Every write audits through `writeAudit`, which counts against the demo write cap (D-033). Commands that create or resolve use `Idempotency-Key` through `idempotent()`.
- Error handling: a class and a code, never provider text. `FAILURE_POLICY` in `backend/src/integrations/types.ts` is the pattern for sink errors.
- Any new table needs RLS, write policies, composite keys, a purge line and, if seeded, a pack copy. `schema.test.ts` sweeps every table with a `workspace_id` after a purge. The pack is at 38 rows of a 40 maximum.
- `scripts/lib/template-data.mjs` imports `backend/src/domain/reconcile.ts` and `backend/src/integrations/mappers.ts` directly under Node, so keep those two free of value imports.
- Local runs need Node 22 on the path. The default shell is Node 26, and CI uses 22.
