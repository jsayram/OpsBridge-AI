## NetSuite focus

The ERP Simulator follows SuiteTalk REST conventions from Oracle's public help pages: the record collection shape, ID stubs in collections, the offset-divisible-by-limit rule, SuiteQL with `Prefer: transient`, and the `o:errorDetails` body. `docs/design/INTEGRATION-CONTRACTS.md` lists each convention, its source, and the known gaps. The data is original. This shows design knowledge and is **not live NetSuite experience**, which stays an explicit gap under JOB-03.

## Independent review

A separate agent reviewed the code diff with no conclusions supplied, and it reproduced findings on a throwaway copy. This is an AI review, not a human or independent security audit. It found no workspace, guest or secret-leak path, and two High defects. I checked each against the code. All are fixed with tests except the items marked.

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | High | Resuming an old failed run after a newer success marked 4 of 5 live records deleted, and could move the cursor backward | `run_superseded`, and the cursor can't move back |
| 2 | High | Disconnect left a running run alive, which restored `Connected Test`, and a late refresh could restore a scrubbed token | Disconnect ends running runs, refresh writes only to a live row |
| 3 | Medium | A rejected record counted as deleted, and a read with one stream missing could delete the other | Deletion needs a clean full read that returned that type |
| 4 | Medium | A decrypt failure stranded the run and blocked the scrub; missing config blocked disconnect; taking over a crashed run was unbounded | Fails cleanly, always scrubs, takeover counts against the bound |
| 5 | Medium | Resume ignored a disconnected connection | `not_connected` |
| 6 | Medium | A token refresh inside the retrying transport could be abandoned and repeated | Refresh moved outside it, with its own timeout |
| 7 | Medium | Approval didn't recheck the source, so a reverted rename could still be written | `evidence_stale` against the newest stored record |
| 8 | Medium | Invoice changes to bill-to, currency or date were lost, and in-page dedupe kept the first copy | All fields compared, `customer_id` follows the bill-to, newest wins |
| 9 | Low | OAuth state stayed usable after a failed exchange, and the exchange ran inside a transaction | State burns in its own commit first, no transaction across the call |
| 10 | Low | Detection used an unordered cap | Ordered, and detection skips rather than reporting a partial picture |
| 11 | Low | Inventory could show an older version as current after an item change | Newest first, then filtered |
| 12 | Low | Labels would be wrong once a real org connects, and "Owner test mode" showed before any connection | Labels follow the connection |
| 13 | Low | The target picker preselected the name-based suggestion | Nothing preselected |
| 14 | Low | Redirects weren't set to manual | Set, and a test covers a redirect from the data API |
| 15 | Low | `seed_demo_workspace` doesn't copy invoices, contacts or mappings | Left as designed: the pack stays small and a sync fills invoices |

`key_version` on `connection_secrets` is unused, since key rotation has no tooling. The runbook covers it by hand.
