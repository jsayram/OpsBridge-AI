## Security, quality and cost

- The assignee refusal doesn't reveal whether an ID exists elsewhere.
- The UI hides or disables what a role can't do and says why. The server enforces it either way.
- The state machine is enforced in the API, not by a database trigger. A bug in a later route could bypass it, so later phases must use these commands.

## Decisions and teaching notes

**Teach-back.** Every workflow command locks the case row first. So a checklist change can't land between "are all items done?" and "move to Ready". Removing that lock made a test fail, which proves it matters. A required item that's flagged can reach a reviewer, since that's who should look at it, but it can't reach Ready.
