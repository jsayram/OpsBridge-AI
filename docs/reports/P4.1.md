## Outcome and scope

Rules now do something. Each one is a trigger from the five event types, a condition built only from listed fields with listed values, and one of two actions. A manager can turn a rule on or off, narrow it, and reuse it for the second fictional team. A read-only preview shows which rules a sample event would match. In a demo workspace every effect is Simulated.

JOB-TEST-06 is met locally: the seeded "Notify ops sheet when approved for Field Services" rule is reused for Seasonal Staffing as a linked rule that differs only in the team. A Seasonal Staffing approval matches only the reused rule, a Field Services approval only the original, and another workspace sees neither. Both run through one evaluator, `matches()` in `backend/src/domain/rules.ts`.
