## What the WebKit runs found

The first WebKit run failed 86 of 110. All four causes were in the test setup, not the app:

| Finding | Cause | Change |
|---|---|---|
| Nothing worked after launch | WebKit doesn't store a `Secure` cookie over plain `http`, even on localhost. Chromium makes an exception for localhost | The WebKit run serves `https` with wrangler's local certificate (`E2E_HTTPS=1`). The cookie stays `Secure`; nothing was weakened |
| Keyboard tour stuck on the first Tab | Safari's Tab key moves through form fields only. A keyboard user reaches links and buttons with Option-Tab, or turns on "Press Tab to highlight each item" | WebKit tests press Option-Tab. Worth one line in the P8 user guide |
| CSV download never arrived | WebKit downloads in a separate process that ignores Playwright's accept-self-signed-certificate setting | On WebKit the test fetches the link's own URL in the page with the same session and checks the same file. The browser's save prompt is not checked in WebKit |
| Intermittent failures, in about one full run in two | Reads before the page settled (checklist before and after a decision, a title typed before the case loaded); a faked 500 whose route outlived Retry; the automations test picking "the last table" before the runs table had loaded | Retrying assertions and waits; a route that fails only once; the runs table found by its label. Each repeated 3 to 12 times clean in WebKit afterwards |

**Not explained, carried to P8:** in WebKit desktop, twice in about eight full runs, a click on "New case" didn't open the form (`security.spec.ts` and `core.spec.ts`, timing out on the title field). The session loads once and nothing remounts the list, so this looks like a click landing during layout in WebKit, but a real Safari user could hit the same thing. It never happened in Chromium. The final WebKit evidence run shows it once, as a test that passed on its retry. Check in real Safari at P8.1.

These fixes also run on Chromium, where they pass.

## Load profile (PRD 13.2)

`node scripts/load-profile.mjs`, 2026-11-09 23:46 UTC. MacBook Pro (Apple M1 Max, 10 cores, 64 GB), Node 22.23.1, wrangler 4.158.0, Postgres 17 in Docker on the same machine. Twenty simulated visitors at once for 60 seconds, each from its own address. Each launches a demo, then repeats list, detail, summary, analytics overview, report, findings and one case edit, pausing 4 to 5 seconds between rounds, which keeps each visitor under the 120-a-minute limit the way a person clicking would.

| Route | Requests | p50 ms | p95 ms | p99 ms |
|---|---|---|---|---|
| Landing page | 20 | 38.9 | 39.2 | 39.9 |
| Analytics overview | 259 | 52.9 | 186.6 | 208.9 |
| Case list | 259 | 35.8 | 107.4 | 151.3 |
| Case detail | 259 | 47.1 | 171.2 | 195.7 |
| Findings | 259 | 33.1 | 95.3 | 111.2 |
| Report | 259 | 40.5 | 125.5 | 150.0 |
| Summary | 259 | 31.9 | 108.1 | 144.5 |
| Case edit | 259 | 44.4 | 107.0 | 159.2 |
| Demo launch | 20 | 269.6 | 475.2 | 507.1 |

1,853 requests in 64 seconds, no error. **The non-AI API p95 target of 500 ms is met at this profile; the worst route is demo launch at 475 ms**, with all twenty visitors launching in the same instant, each copying a workspace. These are local numbers. They say nothing about Workers CPU limits, Hyperdrive or a Neon wake-up, which PRD 13.2 also asks to measure and which wait for a deploy.
