## Outcome and scope

The contracts, failure classes and business definitions exist as code that later packages build on. Mappers are allowlists. The matching engine is a pure function with no score in it, so a fuzzy merge has no code path. The dictionary is data that the app serves and a test holds against `DATA-DICTIONARY.md`. Everything is simulated.

## Decisions and teaching notes

**Teach-back.** Business need: two systems use the word "customer" for different things. Data path: a raw payload goes through an allowlist before anything keeps it. Security boundary: a source can't name a workspace or claim authority. Failure: bad data stops at the mapper. Tradeoff: a new source field stays invisible until someone maps it, which is the point.
