A separate read-only agent reviewed the code with no conclusions supplied. It found no cross-workspace, owner or template path, and no way for the double to reach a hosted config. This is an AI review, not a human or independent security audit. I checked each finding against the code, and all are fixed.

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | High | One IPv6 /64 or one address with resets could fill the 150 cap, locking out everyone for hours. The cap and retention held; availability didn't | Launch and reset share one hourly budget; IPv6 counts by /64 |
| 2 | Medium | Limits came from Worker values and function arguments, so a secret or leaked credential could break the 24-hour rule | Migrator-owned `app.demo_limits`, CHECK on TTL |
| 3 | Medium | No lock or statement timeouts | `lock_timeout`, role timeouts, typed 503. **Not load-tested** |

| 6 | Medium | Hyperdrive caching off was documentation only | Release checklist, smoke's dead-cookie check. Still a manual step |
| 7 | Low | JWKS refetched per request | Own cache with a refetch limit |
