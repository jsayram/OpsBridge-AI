## Outcome and scope

Built and tested against a labeled in-process double only. **P5.3 is Pending Owner Credentials** under DEC-008: no provider account, key or budget exists, and no real provider was contacted. The gateway is off unless every setting is present and under hard caps. It has one allowlisted provider with the URL fixed in code, sends one request with a timeout and no retry, refuses a tool-use or multi-block answer, counts requests, tokens and estimated cost per workspace and day in the database, and reserves the call and checks concurrency under a row lock before calling. Any refusal or failure gives the owner the labeled fixture with a `degraded` code. In a local environment only the double can be used; tests also load a socket guard that refuses every outside host.

## Independent review follow-up

- **Fail-open environment (Low, fixed).** The real network is used only when `ENVIRONMENT` is exactly `staging` or `production`; unset or misspelled is refused with `live_ai_environment_unknown`.
- **Uncounted usage (Low, fixed).** A paid call whose answer is refused (output limit, tool-use or extra blocks) still adds its reported tokens and cost to the day's usage and to the failed row.
- **Quota race (Low, fixed).** The daily review quota is now a counter row locked for each review, shared with the live budget. Three parallel requests at 24 of 25 give one 201 and two 429.
- **Network guard limits.** It covers Node sockets, TLS and `fetch` in every Vitest worker. It does not cover `dns`, `dgram`, child processes, Vitest global setup, or the Playwright and `wrangler dev` processes; those don't run test code that calls providers.
