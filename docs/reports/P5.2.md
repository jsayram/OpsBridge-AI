## Outcome and scope

Done locally. One provider-neutral contract, `doc-review-v1`, and one validation path for every source of output. The fixture answers were produced at build time by a labeled-line extractor that never sees the expected results, and are stored keyed by input hash and prompt version. The Worker replays them through the same checks a live model's output would meet: size, strict JSON, exact keys, closed vocabularies, field rules, citations to real segments whose text contains the value, and consistency. Then deterministic rules, not the suggestion, decide which checklist changes are allowed, and the client name is compared with the case's customer.

## Security, quality and cost

- Fixture answers are deterministic and labeled "Deterministic demonstration fixture" everywhere they appear.
- Honest limit: the extractor misses a client name with two transposed-letter typos (`fx-messy-28`). It is reported as a failure in P5.5 rather than tuned away.
- Cost: $0. No model call.


## Independent review follow-up

- **Citation matching (Medium, fixed).** The first version accepted a value found anywhere inside the cited text, so "yes" matched "eyes" and OB-1234 matched OB-12345. Now `scopeSigned` must be exactly the segment's value part, identifiers match whole and case-sensitive, and names and dates match whole tokens. Tests in `ai-validate.test.ts`. Residual: a segment such as "Note: yes" could still support `scopeSigned` if a model cited it; the label isn't required because the stacked and typo layouts have none on the value line.
- **Client match (Medium, fixed).** Every `done` change now needs the document to name this case's client. Another client's document can only flag the client contact (D-064 updated).
- **Silent sweep (Low, fixed).** The stuck-review sweep bumps the version and writes a `system` audit row.
- **Trigger (Low, fixed).** `mode`, `validation` and `abstain_reason` are frozen while a review waits for a decision. The fixture foreign key is validated by the seed.
