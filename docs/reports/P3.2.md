## Outcome and scope

Simulated CRM, ERP and inventory sources run through one pipeline. The ERP Simulator answers in the SuiteTalk REST shapes from Oracle's public help pages, and the sync reads through SuiteQL. Each page commits with the cursor after it, and the connection's cursor moves only when a whole run succeeds. A replay adds no business record. Nothing here is a real NetSuite connection.

## Decisions and teaching notes

**Measured:** a whole ERP sync took about 20 ms of CPU under Node, CRM about 13 and inventory about 18, in-process with the test harness. Workers Free allows 10 ms. That isn't a workerd number, so it isn't a failed proof, but it is why hosted runs do one page per request. The first deploy has to measure it.

**Teach-back.** Business need: pull data in without ever double-counting. Data path: simulator, adapter, mapper, one page and its cursor in one short transaction. Security boundary: a guest route can only build a simulator. Failure: a crash repeats a page and never skips one. Tradeoff: the simulator follows published conventions, and only a real sandbox can show where it differs.
