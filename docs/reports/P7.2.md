Report time: 2026-11-09 America/New_York. Parent phase: P7. PRD v1.4, SHA-256 `95b85b6a6e817d9aabdadf8534f3cb7a0e196ec0408e733c6771752ef2ef5785`. Writer: P7 phase session (Claude Opus 5.5). Branch `phase/p7-release-gate`, not pushed.

## Outcome and scope

Every operation in the API was called by the wrong caller, and every external provider was taken away in turn, locally. Nothing leaked, nothing was written that shouldn't be, no 5xx came back from a refused call, and the visitor's whole path kept working with each provider down and with all of them down. The intermittent P3 purge-list test was reproduced, explained and fixed. Done locally; nothing hosted.

## Security, quality and cost

- No privilege or tenant leak, no model-created write, no unbounded charge found.
- One semantic note: a Salesforce callback during an outage answers a typed `502 provider_rejected`. That is the API's one intended 5xx for an upstream failure, and the test now requires exactly that code.
- The purge-list cause: `expired_demo_workspaces` returns the five oldest. Since P5 and P6 other files leave workspaces expired minutes ago, and Vitest orders files by cached duration, so a victim expired one minute ago could miss the batch. The function is right; the test assumed it ran first.
- Cost: none.

## Decisions and teaching notes

D-079. **Plain language:** a "fingerprint" is a hash of every row a workspace owns. Taking one before and after an attack proves the attack changed nothing, rather than trusting that a 404 meant no write.
