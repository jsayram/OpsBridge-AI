## Security, quality and cost

- Runtime grants are narrower than PRD 7.4 allows (D-028). Tables no P2 route writes are SELECT only, and handoffs and the outbox can't be updated.
- Every demo write audits, so a trigger on `audit_events` caps a workspace at 500 writes. Without it, one session could write at the API rate limit for two hours. Only a migration can change the cap.
- `external_record_links.canonical_id` and `reconciliation_findings.entity_id` have no foreign key because they point at more than one table. P3 must scope them in code, and the P3 brief says so.
- AI review immutability has no database guard yet. The runtime role can't update that table at all until P5, which must add the guard with the grant.

## Decisions and teaching notes

**Teach-back.** Two transactions each held the lock the other wanted, so Postgres killed one after a second. That only happened when a workspace expired in the milliseconds a reset was running, so it would have shown up as a rare, baffling failure. Now both take locks in the same order, and the purge leaves a workspace alone for a minute after expiry.
